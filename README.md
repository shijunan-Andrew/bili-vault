# 哔哩藏库 Bili Vault

> 把 B 站收藏夹完整搬到本地：可搜索、可筛选、可离线，视频被删了也还在。

这是一个 Chrome Manifest V3 扩展。它监听 B 站视频页的收藏夹弹窗；用户确认后，等弹窗成功关闭，再将视频信息和封面写入你选择的本地目录。扩展不拦截或改写 B 站页面的网络请求。

2.3 延续失效视频恢复和本地去重功能，并调整日常操作界面：单条和批量整理统一为“移动或复制”收藏夹选择窗口；勾选原收藏夹时保留原文件并复制到所选收藏夹，未勾选原收藏夹时移动。插件弹窗常态展示 B 站收藏夹选择列表，开始导入后切换为进度面板；最近状态默认只显示结果摘要，具体保存位置可展开查看。网页和弹窗使用柔和的青绿、暖灰配色，并调整了弹窗宽度和列表高度。

3.0 增加独立的下载页面：可以从视频详情或批量管理打开，也可以手动输入视频网址、BV 号或 av 号；解析后可选分 P、清晰度、格式、视频编码、音频音质，以及视频、音频、弹幕、字幕、封面和信息文件。下载目录由用户选择，扩展会记住上次目录并在需要时请求重新授权。页面展示解析、保存进度和每项下载结果。

3.1 将网页、下载页和插件弹窗的主色恢复为 B 站蓝色，并保留新增收藏夹、下载、删除和异常提示等对比色。左侧收藏夹可拖动上下调整顺序，顺序保存在扩展中；插件弹窗的“打开本地收藏库”移到自动归档开关下方；本地收藏库增加“刷新”，重新扫描当前选中的本地目录。

3.2 默认下载到本地收藏根目录下的“000视频下载”文件夹，首次下载时自动创建并复用该目录；已在旧版选择过自定义目录的设置会继续生效，也可在下载页切回默认位置。下载完成后，视频卡片显示“已下载”标记，详情页可打开该视频对应的本地目录查看文件。收藏库会在下载后同步状态，并定期检查目录内容；目录中的文件全部删除后会撤销标记和详情页入口。

3.3 修正了下载目录中 BV 号的匹配，下载完成后可正确关联回收藏卡片和详情页。下载过程中可以暂停并继续；点击取消会删除本次任务新建的视频目录及其中的部分文件，之前已完成的下载目录不会被删除。

3.4 将插件弹窗的“打开本地收藏库”改为更醒目的绿色大按钮；放大视频卡片右上角的“已下载”标记、已下载视频标题，以及视频详情中的标题、信息字段、简介和标签文字。详情页的“打开本地视频目录”可通过 Windows 原生辅助程序唤起文件资源管理器。

3.5 修复 Windows PowerShell 5.1 安装原生目录助手时中文脚本编码导致的解析错误；收藏库增加“全部视频 / 已失效视频 / 已下载视频”筛选，放大卡片收藏夹、UP 主和日期信息，并将 UP 主主页变为可点击链接。下载按钮改为深绿色；下载默认保存到 `000视频下载/收藏夹名称/视频目录`，错误报告保存到 `001错误报告`。插件导入操作改为“导入或更新”，本地已存在收藏夹时仅追加未收录视频，并提醒控制批量请求数量；弹窗增加绿色收藏库按钮、未设置目录提示、支持作者入口和版本号。

3.6 Stable 修复从本地收藏库发起下载时没有把收藏夹名称带入解析队列的问题。下载队列通过扩展临时存储交接，收藏夹名称不再塞进网址参数；下载目录按“收藏夹/BV 或 av 号”复用，避免重复下载不断新建副本。卡片的“已下载”只在目录内存在视频或音频媒体文件时显示，封面、字幕和信息文件仍可单独打开目录查看。取消任务只清理由本次新建的目录，不会删除先前的已完成文件。

3.7 修复下载目录创建成功后因日志引用了未定义变量 `directory`，导致视频下载立即失败并留下空目录的问题。保存位置日志现在读取实际创建或复用的 `directoryInfo.directory`。

3.8 修复“使用安装 BAT 后点击打开本地视频目录仍然失败”的问题，该问题有两个独立原因：一是原生消息清单把 PowerShell 启动参数写进了 Chrome 不支持的 `args` 字段，Chrome 于是启动了一个没有任何参数的 `powershell.exe`，消息协议当场损坏；二是设置文件 `settings.json` 以无 BOM 的 UTF-8 保存，而 PowerShell 5.1 的 `Get-Content` 默认按系统 ANSI 代码页读取，中文下载路径被解坏后 `ConvertFrom-Json` 直接报错。现在清单的 `path` 指向编译出来的宿主启动器 `folder-opener-launcher.exe`（不再使用 `args`），宿主始终以 `-Encoding UTF8` 读取设置，失败时回传协议内的中文原因；同时新增安装后自检脚本，并在视频详情中加入“复制视频目录路径”作为退路。

4.0 是一次纯界面改版，**没有改动任何归档、导入、下载与原生助手的逻辑**，磁盘目录结构和 `视频信息.txt` 字段完全不变。主要变化：

- **统一设计系统**：新增 `theme.css` 作为唯一的颜色、圆角、阴影、间距、字号、动效来源；`library.css`、`download.css`、`popup.css` 全部重写为单层规则。3.x 那种“2.3 覆写一次、3.1 再覆写一次、3.4 再覆写一次”的层叠补丁不再存在，同一个按钮不再被定义三四遍。
- **换成真正的图标**：新增 `icons.js`（30 个 24px 线性 SVG），替换掉原来混用的 `▦ ▤ ▶ ♫ ↻ ＋ ⌕ ⠿ ✦` 等字符图标。
- **可读性**：建立 `11 / 12 / 13 / 15 / 18 / 22 / 27px` 字号阶梯，取消所有 8px、9px 文字（下载页日志从 9px 提到 13px）；灰阶整体加深，正文与字段名达到 WCAG AA 对比度。
- **布局**：视频卡片改为自适应列宽（宽屏自动 4–5 列，不再是固定的 3 大列）；详情面板把 5 个同权重全宽按钮改成“主操作并排 + 次要操作 + 危险操作分离”；插件弹窗把“导入或更新”折叠成可展开区块，默认视图控制在 Chrome 弹窗 600px 高度以内。
- **人性化**：欢迎页改为“三步开始”引导；搜索命中在卡片标题里高亮；BV 号与视频链接一键复制；详情页显示本地下载体积；简介过长时折叠并可展开；批量模式支持 Shift 连选与 Ctrl/⌘+A。
- **B 站页面上的归档提示卡**：跟随系统深浅色、滑入动画、鼠标悬停暂停自动关闭，归档成功后可直接跳到本地收藏库。
- **顺手修掉的旧问题**：删除已无任何引用的 `download-folder.html/js/css`；侧栏版本号改为从 manifest 读取（不再写死）；补齐键盘焦点样式与 `prefers-reduced-motion` 支持；统一细滚动条。

4.1 修复与改进（同样没有改动归档、导入、下载逻辑）：

- **修复视频简介被写进“标签”的错位 bug**。详情面板在标签为空时插入的占位符复用了 `.detail-description` 类，而后续 `querySelector(".detail-description")` 取到的正是这个占位符，于是简介被覆盖到“标签”下面，真正的简介区永远空白。下载过的视频通常有真标签、不生成占位符，所以看着正常；导入的视频标签是“未知”（被解析为空）→ 触发占位符 → 出错。现在占位符改用独立的 `.detail-empty` 类。
- **占位值按“无数据”处理**：归档文件里缺失的字段会写成 `未知`、`无`、`-` 等，这些不再被当成标签或简介内容，而是显示“这个归档没有记录标签 / 简介”的空状态。
- **已下载视频的标题显示为绿色**（失效视频仍为红色）。
- **收藏库分页**：参考 B 站页码样式，支持上一页/下一页、页码窗口与省略号、`共 N 页 / M 个，跳至 X 页`、每页 24/48/96 个；切换收藏夹、搜索、筛选、排序时自动回到第 1 页。
- **网格 / 竖列两种显示方式**，右上角一键切换，选择会被记住。
- 新增 `test/archive-audit.cjs`：对本地归档做一次体检，统计有多少条记录其实没有标签或简介。用法：`node test/archive-audit.cjs "<你的收藏根目录>"`。

### 4.1beta：补全缺失的标签和简介

这是一次**涉及底层逻辑的改动**（会调用 B 站接口并改写本地 `视频信息.txt`），所以单独出一个 beta 目录，编号 4.1.1。

**为什么会有缺失**：导入流程里只有**失效视频**会去抓标签和简介；正常条目的标签字段恒为空、简介字段常为空，于是归档里写着「未知 / -」。

**改了什么**：

1. **导入时补全**：正常条目现在也会调用 `/x/web-interface/view`（取简介，并顺带补上分区、时长、发布时间、UP 主、封面）和 `/x/tag/archive/tags`（取标签）。只补缺失字段，已有内容绝不覆盖。每次导入最多补 30 条、并发 2、每条间隔 420ms，超出的条目会在报告里提示。
2. **收藏库增量补全**：本地收藏库右上角新增「补全缺失资料（N）」按钮。它会统计当前范围内的缺失条目，让你选择本次处理 10 / 20 / 40 条，逐批推进直到补完。**这是给已经躺在硬盘上的老档案用的** —— 因为导入会按 BV/av 去重，老记录不会再次导入，只能就地补。
3. **写回是外科手术式的**：只替换 `【标签】` 那一行和 `【视频简介】` 区块，其余内容逐字不动。写入前还会做完整性校验（必须仍有 `【基本信息】` 和 `【视频简介】`、长度不得腰斩），不通过就跳过这条。

**安全试跑**：`node test/enrich-trial.cjs "<你的收藏根目录>" 3` 会在**只读**扫描后取 3 条实际调用接口，把补全结果写到 `test/_trial/` 下的副本，**绝不改动原文件**，用来确认效果和接口可用性。确认没问题再在扩展里点「补全缺失资料」正式落盘。

**风控建议**：一次 20–40 条、分几次点完，比一次性点几百条安全得多。失败或接口没返回的记录会保持原样，可以之后再补。

### 4.2：导入重构 + 暂停取消 + 网页端展示优化

**插件端**

- **导入的每条视频都抓一次完整资料**：`/x/web-interface/view` 取简介、发布时间、分区、时长、UP 主、互动数据，`/x/tag/archive/tags` 取标签，`/x/relation/stat` 取 UP 主粉丝数（按 UP 缓存，同一个 UP 只请求一次）。以前只有失效视频会抓，正常条目标签恒为空、简介常为空——现在不会再出现「未知 / -」。
- **本地没有同名收藏夹时全量导入；已有同名收藏夹时，补齐缺失的视频，并按新格式刷新数据不完整的旧记录**（缺粉丝数/互动数据，或标签、简介、发布时间还是占位值的）。
- **导入过程中可以暂停、继续、取消**。取消会删除本次新建的视频目录、还原本次更新过的 `视频信息.txt`、清掉本次新建的空收藏夹，**导入前就在本地收藏夹里的内容不会被删除**。弹窗关闭再打开也能看到当前进度并继续操作。
- **`视频信息.txt` 排布调整**：新增 `UP主粉丝数` 与独立的 `【互动数据】` 区块（播放量/弹幕量/点赞数/投硬币枚数/收藏人数/转发人数），统计信息不再挤在简介里。
- **简介会自动清理**：收藏夹接口返回的 `intro` 常常是 B 站分享文案（`…, 视频播放量 71953、弹幕量 82…, 视频作者 XXX, 作者简介 YYY, 相关视频：…`），4.2 把真正的简介与统计信息拆开，简介里不再夹带这些内容。

**网页端**

- 顶部显示**本地收藏夹占用空间**（递归统计整个根目录）。
- 详情面板把互动数据做成**独立统计卡片行**，UP 主旁边显示粉丝数；没有数据的旧记录不显示这一块。
- 删除了「补全缺失资料」按钮——导入/更新现在会直接把资料抓全。
- 顶部新增提示：如果需要导入或更新本地文件夹内的视频，请在 B 站收藏夹页面点击插件的「导入或更新」。

**试跑**：`node test/import-trial.cjs "<你的收藏根目录>" 3` 会只读地预览 4.2 会抓到什么（标签、发布时间、粉丝数、互动数据、清理后的简介），不改任何文件。

### 4.3：安全与合规加固

**没有新增功能**，只是把审计发现的问题修掉，详见下文「合规与使用边界」。

- 导入请求密度降到**串行 + 每条间隔 800ms**（原先并发 2 + 350ms）。
- 失效视频恢复改为可选开关（它会伪造官方 iOS 客户端请求 APP 接口，是合规上最勉强的一环）。**4.4.1 起默认开启**，可在弹窗里取消勾选关闭。
- 本地收藏库**拒绝被任何页面 iframe 嵌套**；同时不再把 `library.html` 作为 web_accessible resource 暴露给 B 站页面，「打开本地收藏库」改由后台 `chrome.tabs.create` 完成。
- 封面地址增加协议白名单（只接受 `blob:` 与 `data:image/`）并转义。
- 错误报告头部加入「含本地路径、请勿公开分享」提示。

### 4.4：使用须知 + 更新视频状态

**使用须知**：本地收藏库、下载页、插件弹窗三处都加了同一份「使用须知」，内容包括——

- 自带的下载器并不稳定，大批量下载建议改用 [DownKyi](https://github.com/leiurayer/downkyi) 等工具；
- 下载的文件只用于个人离线观看，不要在网络上传播、分享或二次发布；
- 请勿滥用：请求过密可能触发风控，导致 IP 或账号被临时限制，请分批、低速使用；
- 本插件不是 B 站官方工具，使用它可能违反《哔哩哔哩用户使用协议》（第 4.3.15 条等）；
- 插件不会修改你 B 站账号里的任何数据，所有请求都是只读的；
- 所有文件都保存在本机，插件不上传任何数据，也没有任何遥测。

三处都是**黄色提示条**（4.4.1 起）、正文字号 15px。收藏库里默认展开、点击标题可折叠，但**不提供「不再提示」**；下载页常驻；弹窗里置顶、默认折叠（避免把 600px 高的弹窗撑开）。

**更新视频状态**：收藏库右上角新增「更新视频状态」按钮。它会重新解析每条记录，**覆盖更新那些会变化的数值**——播放量、弹幕量、点赞数、投硬币枚数、收藏人数、转发人数和 UP 主粉丝数（另外只在原值为「未知」时补上发布时间）。

- **只动这些数值**，标题、简介、标签、收藏时间、保存文件夹、目录结构全部逐字不动。
- **如果解析发现视频已失效，不会覆盖任何原有资料**，只在文件里写入一条失效标记；网页端随即按失效视频处理——「已失效」徽标、标题变红、封面加灰色蒙层，与导入时识别出的失效视频表现一致。
- 如果一条之前被标记失效的记录又能正常访问了，更新时会自动把标记改回「正常」。
- 同样分批进行（10/20/40 条），对话框里有风控提示，处理完可以再点一次继续。
- 网络错误不会被误判成失效：只有 B 站接口**明确返回错误码**（如 -404、62002）才算失效，超时或断网只会记为失败、文件保持原样。

收藏夹移动或复制时会一并复制关联的下载目录；移动时再清理来源下载目录。删除视频或收藏夹可在确认窗口中选择是否同时删除关联下载，默认不勾选。下载失败会尝试写入根目录的 `001错误报告`。旧的“未分类收藏”下载仍可按 BV/av 号识别并在移动或删除时纳入处理。

稳定性回归检查覆盖收藏夹传递、下载目录编号识别、旧版目录回退匹配、媒体文件徽标判断和收藏夹名称安全处理。可在安装 Node.js 的环境中运行：`node test/stability.test.cjs`。

## 安装

1. 在 Chrome 打开 `chrome://extensions`。
2. 打开右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本项目文件夹。
4. 点击工具栏中的“B站收藏信息归档”，选择本地保存文件夹。
5. 打开 B 站视频页并收藏视频。保存结果会在视频页右下角弹出。

## 保存结构

```text
所选根目录/
└── 收藏夹名称/
    └── 2026年10月08日21时05分30秒/
        ├── 封面.png
        └── 视频信息.txt
```

同一收藏夹在同一秒内发生多次保存时，后续记录目录会自动添加 `_2`、`_3` 等后缀，避免覆盖已有文件。

## 从 B 站收藏夹导入

1. 在 Chrome 中打开已登录账号的 B 站个人空间收藏夹页面（`space.bilibili.com/.../favlist`）。
2. 点击插件图标，选择“导入或更新”，勾选要导入的收藏夹，然后点击“开始导入”。
3. 视频会按“收藏夹名称/收藏时间”归档到已选择的本地根目录。若目标本地收藏夹已有相同 BV/av 号，会提示“已存在相同视频”并跳过重复项，只导入缺少的条目。
4. 对失效视频，插件会尝试从 APP 收藏夹接口、稍后再看、观看历史和视频资料接口找回标题、封面、UP 主、简介、时长、分区、发布时间和标签。APP 收藏数据会跨页扫描并重试，某页失败时仍保留已读取的恢复结果。未找回的字段记为“未知”；封面无法找回时会保存占位封面，确保本地收藏库仍能显示这条记录。
5. 单条视频或收藏夹导入失败时，其余条目仍会继续处理；错误报告会写入根目录下的“001错误报告”文件夹。请避免一次导入过多内容，以免频繁 API 请求触发 B 站风控。

失效视频只有在 B 站仍保留于 APP 收藏、历史记录、稍后再看或视频资料等来源时才能找回；如果这些来源都没有留存，插件会按“未知”保存缺失字段。

导入仅读取 B 站收藏数据，不会修改线上收藏夹。

## 错误报告

保存失败时，扩展会尝试在所选根目录的 `001错误报告` 子目录中写入报告。若目录不可访问，错误报告会留在扩展弹窗中，可通过“下载错误报告”保存到本地。

## 本地收藏库

点击扩展弹窗里的“打开本地收藏库”，首次选择归档根目录后，页面会记住该目录；之后重新打开时会自动读取，若 Chrome 要求再次授权，可继续使用上次目录，无需重新选择。页面只解析符合“根目录 / 收藏夹 / 时间戳目录 / 视频信息.txt + 封面.png”结构的视频记录，支持按收藏夹筛选、搜索、排序；点击视频卡片可查看信息并跳转到 B 站原视频。目录内容仅由浏览器在本机读取。

网页可新建或删除本地收藏夹，也可选择一个或多个目标收藏夹添加视频。输入 B 站视频网址、BV 号或 av 号后，扩展会向 B 站查询视频资料，再分别写入未包含该 BV/av 号的收藏夹；遇到重复项会提示“已存在相同视频”并跳过该收藏夹。

在视频详情或批量管理中点击“移动或复制”，可以同时选择多个目标收藏夹。勾选视频原所在的收藏夹时会保留原文件并复制到其他已选收藏夹；不勾选时会把视频放入所选收藏夹并删除原位置。目标收藏夹已有相同 BV/av 号时会提示并跳过重复项，其余目标继续处理。删除视频或整个收藏夹前会请求本地目录写入权限，并显示确认提示。

点击“批量管理”后，视频卡片会显示勾选框，可全选当前筛选结果，再把多个视频移动或复制到一个或多个收藏夹，或批量删除。批量删除前会显示确认提示；失败的视频会保留选中，便于重试。筛选菜单可切换全部、已失效或已下载视频；失效封面加灰色蒙层，标题显示为红色。

如果浏览器回收了本地目录的写入授权，扩展弹窗会显示“重新授权保存位置”。授权后，近期失败且已暂存的视频会自动补存；较早版本失败时没有暂存内容，需要在 B 站重新收藏一次。

## 下载视频

1. 在本地收藏库的视频详情中点击“下载视频”，或在“批量管理”中选中多条视频后点击“下载”；也可以在下载页粘贴视频网址、BV 号或 av 号。
2. 默认位置为本地收藏根目录下的 `000视频下载/收藏夹名称` 文件夹，开始下载时会自动创建并复用。也可选用自定义目录，之后随时切回默认位置。选择清晰度和要保存的内容后点击“开始下载”。多 P 视频可选择全部分 P 或单个分 P。
3. MP4 模式保存 B 站提供的音视频合并流；如果接口没有提供 MP4 单文件，可切换到 DASH。
4. DASH 模式会将视频和音频分别保存为 `.m4s` 文件。浏览器扩展不包含 DownKyi 的 FFmpeg，因此不会在下载页合并生成 MP4。
5. 封面、弹幕、字幕和视频信息按各自文件保存到每个视频的独立目录。不可用内容会在进度区标记失败，其他内容和队列中的其他视频会继续处理。
6. 目录内存在视频或音频媒体文件时，收藏库的视频卡片会显示“已下载”。安装下方的 Windows 辅助程序后，详情页的“打开本地视频目录”会直接打开对应的资源管理器文件夹；未安装时会提示安装方式。删除目录中的所有文件后，收藏库在前台约 60 秒内或重新显示时会撤销标记和入口。

下载需要登录 B 站并且账号有权访问相应内容。实际可用清晰度、音轨、字幕和弹幕由 B 站接口及视频本身决定；失效或受限视频可能无法下载。出现下载失败时，扩展会将错误条目写入收藏根目录的 `001错误报告`；如果浏览器没有授予根目录写入权限，进度区会显示报告保存失败原因。

### Windows 文件资源管理器

Chrome 不允许扩展页面直接启动 Windows 文件资源管理器。若要使用详情页的“打开本地视频目录”，需要一次性安装随插件提供的原生辅助程序：

1. 先在 Chrome 中加载 `b_catch_4.0`，打开 `chrome://extensions`，复制本插件的扩展程序 ID。
2. 双击 `install-native-folder-opener.bat`，粘贴扩展程序 ID 和下载目录完整路径。默认位置应填写“收藏根目录\000视频下载”；若下载页设置了自定义目录，则填写那个自定义目录。
3. 在 `chrome://extensions` 中重新加载本插件，然后完全退出 Chrome（关闭所有窗口，必要时在任务管理器结束 chrome.exe）并重新打开。
4. 打开本地收藏库，点击“打开本地视频目录”。

安装脚本会用 Windows 自带的 C# 编译器把 `native\folder-opener-launcher.cs` 编译成宿主启动器 `folder-opener-launcher.exe`，放进 `%LOCALAPPDATA%\BcaFolderOpener`，并写入 Chrome 原生消息清单和当前用户注册表。**扩展程序 ID 是由插件所在目录决定的**：换了插件目录（例如从 `b_catch_3.8` 换到 `b_catch_4.0`）ID 就会变，此时必须用新 ID 重新运行一次安装脚本。

安装后可以先做一次不依赖 Chrome 的自检（不会打开资源管理器）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-native-folder-opener.ps1 -CollectionName "收藏夹名称" -DirectoryName "视频目录名称"
```

如果原生助手不可用，“打开本地视频目录”会在视频详情里保留完整错误原因，并提供“复制视频目录路径”：助手可用时复制完整绝对路径，不可用时复制“收藏夹\视频目录”相对路径，可手动粘贴到资源管理器。

辅助程序只会打开配置的下载目录中的“收藏夹/视频”子文件夹。它以当前 Windows 用户权限运行，不需要管理员权限；卸载时运行 `uninstall-native-folder-opener.ps1`。如果更换扩展程序 ID 或下载目录，需要重新运行安装脚本。安装前 Chrome 会提示扩展新增了“与协作的原生应用通信”权限。

## 开关与本地整理

扩展弹窗中的开关控制自动归档；开启时工具栏图标为蓝色，关闭时为灰色。关闭自动归档不会影响本地收藏库。打开视频详情后，可将归档目录移动或复制到本地收藏夹，也可删除这条视频的本地归档文件；这些整理操作不会修改 B 站账户中的收藏。

### 4.5：主题、多语言与若干交互调整

**主题切换**：收藏库左下角新增「主题」，可选 **跟随系统 / 白天 / 夜晚**。深色模式不是在页面里写两套样式，而是在 `theme.css` 里替换一组颜色令牌——4.0 建立的令牌体系在这里回本了，三个页面（收藏库、下载页、插件弹窗）一行 CSS 都没改就一起支持了深色。设置存在 `localStorage` 并**在 `<head>` 里同步应用**，所以不会先闪一下浅色。

**多语言**：收藏库左下角、插件弹窗页脚新增「语言」，可选 **简体中文 / 繁體中文 / English**。实现方式是**用中文原文当 key**：简体中文不需要任何词典文件（查不到就原样返回），`locales/zh-TW.json` 与 `locales/en.json` 只存需要改写的条目。**只翻译界面文字**——视频标题、UP 主名、简介、标签、BV 号这些固有名称一律不经过翻译层。**目录名与文件名也逐字保留**：界面上的 `000视频下载` 就是磁盘上的 `000视频下载`，任何语言下都不译，否则你会看到界面上的名字却找不到对应文件夹。

**已知边界**：后台产生的运行时文案（导入进度、错误消息、`001错误报告` 的正文）保持简体中文，不随语言切换——它们属于归档数据，保持单一语言便于长期比对。

### 面向维护者：多语言的两个检查工具

```powershell
node test/i18n-extract.cjs           # 列出全部待翻译词条
node test/i18n-extract.cjs --todo    # 生成 locales/_todo.json（交给翻译）
node test/i18n-extract.cjs --check   # 校验词典覆盖率（回归测试也会跑）
node test/_unmarked.cjs              # 反向检查：找出漏标记的界面文字
```

`i18n-extract` 只能证明「已标记的能翻」，`_unmarked` 补上「该标的都标了」这一半。4.5 就是靠它发现 `library.js` 有 74 处、`download.js` 有 46 处漏标记——界面看着正常，切到英文却纹丝不动。加了新的界面文字之后请两个都跑一次。

**筛选与展示**：

- 排序新增「**播放量从高到低**」。没有播放量数据的记录排在最后（按 -1 处理，不会和「0 播放」混在一起），同档再按收藏时间倒序。

**改名**：项目正式更名为 **哔哩藏库 / Bili Vault**。### 4.7：细节修复

- **顶部横幅不再卡住**。原来有两个问题叠在一起：一是轨道只有两份文字宽（约 500px），宽屏上右边会空一大块；二是系统若关闭了「动画效果」，`theme.css` 里那条全局的 `prefers-reduced-motion` 规则会把动画压成「跑一次就弹回原位」——默认的 `animation-fill-mode: none` 会让元素退回无位移状态，看着就像坏了。现在按容器宽度自动补足份数、前后两半严格等宽，并给这条横幅加了一条显式豁免（它本身可关闭，不会困扰不想看动效的用户）。

- **弹窗的「导入或更新」改成醒目的橘黄色**（新增 `--feature` 系列令牌，深浅主题各一套，对比度 4.76 / 7.39）。
- **弹窗简介**改写为面向使用者的说明。
### 4.8：手动标记已下载、失效视频站外搜索

- **「已下载？点击标记」**：如果你习惯用别的下载器，不必为了让它显示成"已下载"而重新下一遍。点这个按钮，插件会在该视频的下载路径里建一个文件夹，里面只放一个说明文件（**没有视频内容**），并把这条记录标记为已下载；随后「打开目录」和「复制视频目录路径」就会出现，你把别处下好的视频拖进去就行。**已经标记过的记录不会再显示这个按钮。**
  - 目录名用和下载器完全相同的一套规则生成（以 ` - BV号` 结尾），所以将来你再用插件下载同一个视频时，它会认出这个目录并直接复用，不会另建一份。
  - 说明文件同时起了"占位"作用：目录里有文件，扫描逻辑不需要为这个功能放宽任何既有条件。
- **失效视频的站外搜索**：失效视频在 B 站已经没有可看的页面了，所以详情页多给了一个「全网搜索该视频」，点击后用 Bing 搜索这个视频的标题。
- **插件顶部加了静态开源横幅**：点击跳到项目主页，可关闭（关闭状态记住）。
### 4.8.1：入口与分页微调

- **每页条数改成 25 / 50 / 100**。原先的 24/48/96 与「一行 5 个」的网格对不上，最后一行总会缺一个。
- **「给 up 一个一键三连」搬到了收藏库左下角**（版本号下方），点击跳转作者的 B 站主页。
- **两个界面都多了一个仓库入口**：「一键三连」旁边是带 Github 图标的 **Github 仓库地址**，点击跳转项目仓库。
- **图标**：顶部横幅文字前加了 Github 标识；「一键三连」前面的星形换成了 B 站标志性的**小电视**（线框版，与其余图标同一套风格）。
### 4.8.2：三个修补

- **收藏夹多了不再把底部挤出去**：侧栏的收藏夹列表现在自己滚动，版本号、一键三连、仓库地址始终留在可视区。
- **「复制视频目录路径」优先给绝对路径**，可以直接粘进文件资源管理器。取路径的顺序是：**Windows 原生目录助手 → 你在下载页手填的下载根目录 → 相对路径**。
  > 为什么需要手填：浏览器出于隐私考虑**不向网页暴露文件夹的绝对路径**（File System Access API 就是这样设计的），插件也没有 `downloads` 权限。所以绝对路径只有两个来源——原生助手读到的，或者你自己填的。**装好原生助手后会自动读取，不用填。**
- **修掉一个真 bug**：「已下载？点击标记」标记过的视频，切到别的界面再回来会变回未下载，要刷新才恢复。原因是「算不算已下载」这条规则被写了两份，加「手动标记」时只改了一份；而页面重新获得焦点时跑的正是没改的那份。现在这条规则**收敛成 `downloadMatchIsDownloaded()` 一个函数**，并且加了测试禁止再出现第二份。
### 4.8.3：对比度与可读性

- **次要按钮不再是白底**。原来「打开目录」「复制视频目录路径」「全网搜索该视频」「已下载？点击标记」是白底深字，压在白卡片上几乎看不出是个按钮。现在统一成品牌浅蓝底（`--brand-deep` on `--brand-soft`，对比度 5.17 / 8.90）。**悬停刻意不加深底色**——`--brand-line` 上的文字只有 4.23，不达标，所以改成加深描边 + 一圈品牌光环。
- **扫描结果通知可以关闭了**。关掉之后记住当时那段文字，**下次扫描结果一样就保持隐藏**，结果变了才重新出现。
- **插件的「导入或更新」折叠态与展开态统一成实心观感**：橘黄底 + 浅橘色图形图标。顺带修掉一个 CSS 顺序问题——4.7 加的橘黄规则写在了基础规则**之前**，同优先级的 `:hover` 被后面的规则盖掉，橘黄悬停其实从来没生效过。
## 合规与使用边界（请务必阅读）

**这个扩展会代替你自动请求 B 站接口并下载内容，因此它触碰了 B 站《用户使用协议》中的条款。** 这一节把话说清楚，请自行判断是否使用。

### 涉及哪些条款

| 条款 | 内容要点 | 本项目涉及的功能 |
|---|---|---|
| **4.3.15** | 未经书面许可，不得以「机器人程式、蜘蛛程式、爬虫程式等**任何自动程序、脚本、软件**」获取平台的服务、内容、数据 | 自动归档、收藏夹导入、批量抓取元数据 |
| **1.2** | 服务「均限于在哔哩哔哩内使用」，以任何方法**将服务与哔哩哔哩分离**的行为不属于约定服务 | 下载视频、音频、弹幕、字幕为本地文件 |
| **1.3** | 官方公布的方式是使用服务的**唯一合法方式**，借由其他途径获取的服务「均为非法」 | 同上；以及失效视频恢复会伪造成官方 iOS 客户端请求 APP 接口 |

| **2.6 / 8.3** | 违反者可被**删除账号、暂停或永久停止服务**，且无需事先通知 | 潜在后果 |

**这不是本项目独有的问题**——所有第三方 B 站下载/归档工具都处在同一位置。协议没有为「个人自用归档」留例外。

### 实际风险有多大

- **最现实的风险是触发风控**（412、临时限制、需要验证码），通常与请求频率和批量规模相关。
- 账号被临时封禁、永久删除属于协议授权范围内的处罚，但**针对个人自用规模极少执行**。
- **真正的法律风险在你自己手里**：把下载的视频、弹幕、字幕**上传、分享、二次发布**，就同时违反协议 6.5 和《著作权法》，性质从「违约」变成「侵权」。

### 请遵守的使用边界

1. **只用于自己的账号、自己有权观看的内容。** 不要用它去抓取他人无权访问的内容。
2. **产出的文件只留给自己。** 不要上传、分享、二次发布，也不要用于任何商业用途。
3. **不要批量轰炸接口。** 导入已经做了限速（串行 + 每条间隔 800ms，约 1.2 次请求/秒），请不要再自行调快；一次选一两个收藏夹，分几次完成。
4. **不要让它长时间无人值守地跑大批量任务。**
5. 参考《著作权法》第二十四条，「为个人学习、研究或者欣赏」使用他人已发表作品属于合理使用——这条边界只覆盖**你自己看**。

### 4.3 为降低风险做的改动

- 导入请求密度下调到**串行 + 每条间隔 800ms**（原为并发 2 + 350ms，约 5.7 次/秒）。
- **失效视频恢复默认开启（4.4.1 起）**：它需要伪造官方 iOS 客户端去请求 APP 接口，属于合规上最勉强的一环。如果你不希望走这条路径，可以在插件弹窗的导入面板里取消勾选「尝试恢复失效视频」。
- 关掉自动归档开关即可完全停止自动行为；不选目录则扩展不会读写任何本地文件。

### 代码层面的安全属性（已核查）

- **从不修改 B 站服务端状态**：全部请求都是 GET，没有 POST/PUT/DELETE，不可能误删你的线上收藏或代替你发言。
- **无第三方域名、无遥测**：出网域名只有 `api.bilibili.com`、`*.hdslb.com`、`*.bilivideo.com/.cn`、`*.akamaized.net`。
- **无远程代码**：没有 `eval`、没有动态加载脚本、MV3 默认严格 CSP，也没有任何 npm 依赖。
- **扩展页不对任何网页开放**：`library.html` 不作为 web_accessible resource 暴露，并额外拒绝被 iframe 嵌套。
- **错误报告含本地路径**，文件里已加提示，请勿公开分享。
