# 版本小节模板（README 最新一版 与 docs/HISTORY.md 共用）

发版时按这个骨架写。`docs/HISTORY.md` 每版一节，标题格式固定成 `## V<版本>：<一句话标题>`；
`README.md` 只留最新一版，**发版前先把上一版整段剪进 `docs/HISTORY.md`**，否则 `release.ps1`
会卡在「README 堆了多版」。

四节都写，缺哪节就说明这版大概没想清楚：

```markdown
## V<版本>：<一句话说清这一版改了什么>

### 改了什么

- **<功能名>**：改之前是什么样、现在是什么样；能点名的函数、文件、消息类型写进去
  （下一个人要靠这些关键词 grep）。

### 为什么

- 每一处改动都要写动机：用户在哪一步被卡住、旧行为会带来什么后果。
  没有动机的改动直接删掉，别留在版本里。

### 踩的坑

- 守卫拦下了什么、脚本为什么失败、哪个假设是错的。
  下一个人重做同一件事时，最需要的就是这一节。

### 没动的

- 刻意保持原样的东西，尤其是「看起来顺手也该改」的那些：写清为什么不改，
  免得下一版又提一遍。
```

几条口径（与 `AI_HANDOFF.md` 的硬规则一致）：

- 标题里不写版本号以外的编号，也**不写行号**（行号会漂，要写就写函数名与消息类型）。
- 「改了什么」里出现的界面文案要和真实文案逐字一致（含标点），i18n 的键就是中文原文。
- 提到测试项数、词典条数时写实际数字，但别写死在本文件里 —— 权威在
  `<!-- test-count:N -->` / `<!-- i18n-count:N -->` 与 `node test/status.cjs`。
- 历史小节是快照，**不追改**：口径变了（比如「更新视频状态」改成「更新视频数据」）就在
  新一版里说明，不改旧版正文。
