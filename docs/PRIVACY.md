# 隐私说明（哔哩藏库 Bili Vault）

> 面向商店审核与用户。**一句话：这个扩展不收集、不上传、不分析任何数据；除了向你自己的 B 站账户拉取收藏资料，它只在你自己点「检查更新」时读一次本仓库的公开版本文件。**

更新时间：2026-10-25（对应 V1.12.11）

## 1. 数据存在哪里

| 数据 | 位置 | 谁能看到 |
| --- | --- | --- |
| 视频信息、封面、归档目录 | 你自己选的「本地备份文件夹」 | 只有本机的你和能读该目录的程序 |
| 设置（外观、语言、每页条数、导入断点等） | `chrome.storage.local` | 只有这个扩展 |
| 目录句柄、背景图、缩略图缓存 | 扩展自己的 IndexedDB（`bili-fav-archiver`） | 只有这个扩展 |
| 报告（`001错误报告` / `002同步报告` / `006报告`） | 归档目录下对应的子目录 | 只有你；正文里的系统用户目录会被掩码（见第 4 节） |
| 统计库 | 归档目录下的 `003database/database.json` | 只有你（纯文本，可自行打开、删除） |
| 导出物（`004导出`） | 归档目录下的 `004导出` | 只有你（归档元数据 JSON、Markdown 清单） |
| 删掉的归档 | 归档目录下的 `005回收站`（保留 30 天后自动清理） | 只有你 |

**没有任何一份数据会被发送到作者或第三方服务器。** 扩展里没有统计 SDK、没有埋点、没有远程日志、没有远程配置，也不加载任何远程代码。

## 2. 会发哪些网络请求（三类，全部是 `GET`）

1. `https://api.bilibili.com/*` —— 读你**自己的**收藏夹列表与视频公开资料（收藏夹、视频详情、标签、UP 主粉丝数）。带浏览器里已有的 B 站登录态（`credentials: "include"`），因为收藏夹需要登录才能读。**只读，不写**：不收藏、不点赞、不投币、不关注、不发评论，扩展没有任何写操作。代码里有一道硬断言：任何不是 `https://api.bilibili.com` 的地址会被直接拒绝。
2. `https://*.hdslb.com/*` —— 下载视频封面图，存进本地归档。这条不带登录态（`credentials: "omit"`）。
3. `https://raw.githubusercontent.com/*` 与 `https://cdn.jsdelivr.net/*` —— **只有你点「检查更新」时**才发一次 `GET`，读本仓库公开的 `version.json`（版本号、日期、下载页、zip 的 SHA-256）。不带任何 Cookie、不带登录态，也不会上传任何东西。这两个域名不需要额外权限，因为对方允许跨域读取（`Access-Control-Allow-Origin: *`）。

除这三类之外，扩展**不会发起**任何网络请求；不会向任何广告、统计或 CDN 服务发起请求。B 站接口的请求频率被刻意压到每秒不超过 2 次（导入时约 1.2 条/秒），避免触发 B 站的访问限制。

### 2.1 两个「不发请求」但会被点开的地方

- **2015 彩蛋页**（`bili-old-2015/`）：一个完全离线的复刻页面，192 张图片都在安装包里，打开时不联网。
- **「全网搜索该视频」**（失效视频的详情页）：这是一个普通链接，点了会跳到必应搜索。跳转发生在浏览器地址栏，扩展本身不发出请求、也不携带任何扩展数据。

**关于「全网搜索该视频」**：失效视频的详情页里有一个「全网搜索该视频」，它是一条普通链接，
点开会在新标签页里跳到必应搜索（网址 `www.bing.com`）。这是你自己点开的网页跳转，**插件本身
不发任何请求**、也不会把任何本地数据带过去；搜索结果页的隐私政策由必应负责。

## 3. 每个权限用来做什么（商店审核对照）

| 权限 | 用途 | 不授予的后果 |
| --- | --- | --- |
| `storage` | 存设置、最近状态、错误报告文本、导入断点 | 设置无法保存，导入断点续跑不可用 |
| `unlimitedStorage` | 归档与统计库可能很大，避免扩展存储被配额卡住 | 大收藏夹可能写入失败 |
| `nativeMessaging` | 可选的「本地目录打开助手」（一个本机 PowerShell 宿主，需你手动安装）：只用来在资源管理器里打开归档目录 | 打不开本地目录，其余功能不受影响 |
| `clipboardWrite` | 复制视频目录路径、复制诊断信息、复制原生助手的清理命令 | 复制按钮不可用（仍会给出可手选复制的文本） |
| `notifications` | 后台归档完成或失败时提示（关掉弹窗也能看到结果） | 没有系统通知，界面内仍会显示结果 |
| `host_permissions`: `api.bilibili.com`、`*.hdslb.com` | 见第 2 节第 1、2 类 | 无法导入或无法下载封面 |

权限清单可以在 `manifest.json` 里逐条核对；这个仓库里**没有任何 npm 依赖、没有构建步骤**，装进浏览器的就是仓库根目录里的这些文件。

## 4. 错误报告里有什么

出错时扩展会在本地归档目录写一份 Markdown，用于你自己排查。正文包含：

- 错误消息与调用栈；
- **掩码后的**路径：系统用户目录（`Users\<用户名>` 与 `Documents and Settings\<用户名>` 这两段）会被替换成 `<用户>`；
- 视频链接（B 站 URL）、收藏夹名、标题、操作名。

**注意掩码的边界**：只有上面这两种系统用户目录会被替换。如果备份文件夹放在 `D:\我的资料\...`、网络盘等自定义路径下，这些路段会原样保留。报告只存在你的本机，不会自动发送给任何人；要贴到 issue 之前，建议先自己扫一眼路径。

想清空就删掉对应目录里的文件；`001错误报告` 会自动只保留最近 50 份。

## 5. 第三方与远程代码

- 不包含任何第三方脚本、字体、图片 CDN 或分析库；
- 不加载远程代码（MV3 要求，本扩展也没有任何 `eval` / `new Function` / 动态 `import`）；
- 唯一的「外部程序」是可选的原生目录助手，脚本随仓库提供、由你手动安装，只做「打开一个已存在的目录」这件事：协议 4 会校验调用方扩展 ID 与白名单，只读 `settings.json`，目标必须落在下载根目录之内，且拒绝 `..` 与设备命名空间路径。

## 6. 删除数据

- **卸载扩展**：`chrome.storage` 与 IndexedDB 里的设置、句柄、背景图、缩略图缓存会随卸载删除；
- **本地归档**：在你自己选的文件夹里，删掉对应收藏夹目录即可（删之前建议先看一眼 `005回收站`，扩展的删除操作会先进回收站保留 30 天）；
- **报告、统计库与导出物**：`001错误报告/`、`002同步报告/`、`003database/`、`004导出/`、`006报告/` 都是普通目录或文件，直接删除即可。
